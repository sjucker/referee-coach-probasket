# Feature: Coach-uploaded video snippets

## Context

Referee-coaches review referees with video reports. Today a report references **exactly one**
externally-hosted video: `report.game_video_url` (a single `varchar(255)`) parsed on read into
`youtubeId` / `asportId`. "Video comments" (`report_video_comment`) are just `timestamp_in_seconds`
offsets into that one video, carrying text, tags and replies.

Coaches now want to **capture short clips on their smartphone at the game and attach them directly** —
without a YouTube/Asport link. There is no file-upload path, no object storage, and Heroku's dyno
filesystem is ephemeral, so this is genuinely new plumbing.

**Decisions made with the user:**
- **Shape:** each upload is a *standalone snippet comment* — a video comment that carries its own clip,
  independent of any full-game video. Multiple per report. Works even for text-only / no-full-video reports.
- **Storage:** S3-compatible object storage. DB stores only metadata + object key; the browser uploads
  and plays back **directly** via short-lived presigned URLs (bytes never touch the dyno → no multipart
  config, no 30s dyno request-timeout problem, no memory pressure). Recommended provider:
  **Heroku Bucketeer** (auto-provisions an AWS S3 bucket + config vars); Cloudflare R2 works too (set an
  endpoint override, no egress fees).
- **Format:** store as-is, play via HTML5 `<video>` (MVP). Accept that some iPhone HEVC/.mov clips may not
  play in all browsers; mitigate with a UI hint to record in "Most Compatible" (H.264) mode. Transcoding is
  out of scope.

## Data model (new migration `V16__report-video-upload.sql`)

Reuse the existing comment/tag/reply machinery — a snippet is a `report_video_comment` with an attached
uploaded file and no meaningful timestamp.

```sql
create table report_video_upload (
    id           bigserial constraint pk__report_video_upload primary key,
    object_key   varchar(512) not null,   -- key in the bucket, e.g. reports/{reportId}/{uuid}.mp4
    filename     varchar(255) not null,   -- original filename (display / download)
    content_type varchar(255) not null,
    size_bytes   bigint       not null,
    uploaded     boolean      not null default false,  -- flips true after client confirms the PUT
    created_at   timestamp    not null,
    created_by   bigint       not null
        constraint fk__report_video_upload__login references login (id) on delete cascade
);

alter table report_video_comment
    add column report_video_upload_id bigint
        constraint fk__report_video_comment__upload references report_video_upload (id);

-- snippet comments have no timestamp into a full video
alter table report_video_comment
    alter column timestamp_in_seconds drop not null;
```

After the migration: **regenerate jOOQ** (`./mvnw clean test-compile -Djooq-codegen-skip=false`, Docker up).

## Backend

### Storage abstraction — new package `service/storage`
- `VideoStorageService` interface: `createUploadUrl(objectKey, contentType, ttl)`,
  `createDownloadUrl(objectKey, ttl)`, `exists(objectKey)`, `delete(objectKey)`.
- `S3VideoStorageService` impl using **AWS SDK v2** (`software.amazon.awssdk:s3` + `s3-presigner`).
  Configured with region + credentials + optional `endpointOverride` so the same code serves
  Bucketeer/S3/R2. Presigned URLs are generated by `S3Presigner` (expiry handled by the SDK — no
  `LocalDateTime.now()`, so ArchUnit stays green).
- New deps in `pom.xml` (`software.amazon.awssdk:s3`, `:s3-presigner`; import the `awssdk:bom`).

### Config — extend `configuration/ApplicationProperties.java` + `application.properties`
```
probasket.storage.bucket        = ${BUCKETEER_BUCKET_NAME}
probasket.storage.region        = ${BUCKETEER_AWS_REGION:eu-central-1}
probasket.storage.access-key    = ${BUCKETEER_AWS_ACCESS_KEY_ID}
probasket.storage.secret-key    = ${BUCKETEER_AWS_SECRET_ACCESS_KEY}
probasket.storage.endpoint      = ${STORAGE_ENDPOINT:}   # empty=AWS default; set for R2/MinIO
probasket.storage.max-upload-bytes = ${MAX_UPLOAD_BYTES:104857600}  # 100 MB
```
(Local dev: point `endpoint` at a MinIO container and set fake creds in `application-local.properties`.)

### DTOs (`dto/report`) — drives `rest.ts` regeneration
- New `CreateVideoUploadDTO(@NotNull String filename, @NotNull String contentType, @NotNull Long sizeBytes)`.
- New `VideoUploadDTO(Long uploadId, String uploadUrl)` — presigned PUT + new upload id.
- Extend `ReportVideoCommentDTO` with nullable, mostly read-only fields:
  `Long uploadId, String videoUrl, String videoFilename`. When `uploadId != null` it is a snippet;
  `videoUrl` is a presigned GET generated on read; `timestampInSeconds` is ignored by the UI.
  Keep `timestampInSeconds` non-null-friendly by defaulting snippets to `0` on insert (avoids rippling a
  nullability change through `of(...)`/`ofReference(...)` and the frontend timestamp typing).

### Endpoints — extend `rest/ReportEndpoint.java` (base `/api/report`, `@Secured("REFEREE_COACH")`)
- `POST /referee/{externalId}/video-upload` (body `CreateVideoUploadDTO`) → `VideoUploadDTO`.
  Validates `contentType` starts with `video/` and `sizeBytes <= max`; verifies the caller owns the report;
  builds `object_key = reports/{reportId}/{UUID}.{ext}`; inserts `report_video_upload(uploaded=false)`;
  returns a presigned PUT URL.
- `POST /referee/{externalId}/video-upload/{uploadId}/complete` → marks `uploaded=true` (optionally
  `storage.exists(objectKey)` to confirm the object landed).
- Playback needs **no** new endpoint: `ReportVideoCommentDTO.videoUrl` is filled with a fresh presigned GET
  in `ReportSearchService` on report load.

### Service wiring (`service/report`)
- `ReportService`: inject `reportVideoUploadDao` + `VideoStorageService`. Add the two upload methods above.
  In `updateRefereeReport` extend the insert branch so a comment with `uploadId != null` is persisted with
  `report_video_upload_id` set and `timestamp_in_seconds = 0`; preserve `uploadId` on existing comments so
  they aren't re-created; on delete of a snippet comment, delete the object (`storage.delete`) + upload row.
- `ReportSearchService.findRefereeReportByExternalId`: in the two video-comment `multiset` blocks,
  left-join `REPORT_VIDEO_UPLOAD` and map `uploadId` / `videoFilename`, then post-map fill `videoUrl` via
  `storage.createDownloadUrl(objectKey, ttl)` for rows that have an upload. (Presign after the query, not
  inside jOOQ mapping.)

## Frontend (`src/main/webapp`)

### `components/video-player/video-player.ts` — add a third source branch
- New input `videoUrl = input<string|undefined>()`. Template: `@if (videoUrl()) { <video #uploadedPlayer
  [src]="videoUrl()" controls [width]="videoWidth()"></video> }`. Implement `jumpTo`/`getCurrentVideoTime`
  against the `<video>` element (`.currentTime`, `.play()`). Snippet cards instantiate their own
  `<app-video-player [videoUrl]="...">`.

### `edit/edit.ts` + `edit.html` — the upload UX (coach only)
- Add an **"Upload video snippet"** button backed by a hidden `<input type="file" accept="video/*" capture>`.
  On file pick: (1) `POST .../video-upload` → get `{uploadId, uploadUrl}`; (2) **PUT the file directly to
  `uploadUrl`** with upload progress; (3) `POST .../complete`; (4) push a new `ReportVideoCommentDTO`
  `{uploadId, comment:'', timestampInSeconds:0, reference:false, replies:[], tags:[]}` into
  `report.videoComments` (mirrors today's `addVideoComment`). The existing full-report `PUT` then persists
  the link. Snippet cards render the `<video>` + text field + tags, but **no "Jump to Scene"** button.
- **Auth-interceptor gotcha (critical):** `app/auth.interceptor.ts` currently adds `Authorization: Bearer`
  to *every* request. The presigned PUT/GET go to the bucket host and must NOT carry the JWT (S3 rejects the
  signature and it leaks the token). Fix: bypass interceptors for absolute non-app URLs — either guard the
  interceptor (`req.url.startsWith('/') / same-origin` only) or issue the PUT via `HttpBackend`.

### `view/view.*` and `discuss/discuss.*` — playback
- Render snippet comments (`videoComment.uploadId != null`) with `<app-video-player [videoUrl]=...>`; gate the
  existing "Jump to Scene" button to non-snippet comments only. Adding snippets stays coach-only (edit) for
  this iteration.

### Regenerate `rest.ts`
`./mvnw typescript-generator:generate` after the DTO changes.

## Infra / ops setup (one-time, document in README)
- Provision the bucket: `heroku addons:create bucketeer:hobbyist -a referee-coach-probasket` (or an R2 bucket
  + set `STORAGE_ENDPOINT`). Set the `probasket.storage.*` env vars.
- **Bucket CORS**: allow `PUT` and `GET` from the app origin (`probasket.base-url`) so the browser can
  upload/download directly. Without this the presigned PUT is blocked by the browser.
- Local dev: add a MinIO service to `src/main/docker` (compose) + `application-local.properties` storage
  config so uploads work end-to-end without touching prod.

## Verification (end-to-end, not just tests)
1. Start MinIO + Postgres (Docker), backend (`./mvnw spring-boot:run`), frontend (`npm start`).
2. As a coach, open/create a video report → click **Upload video snippet** → pick a small `.mp4`.
   Confirm: presigned PUT succeeds (object appears in the MinIO/bucket console), `complete` returns 200,
   a snippet card appears. Save the report.
3. Reload / open the report in **view** → the snippet plays in a `<video>` element. Open **discuss** as the
   reportee → the snippet is visible and plays.
4. Delete a snippet comment in edit + save → the object is removed from the bucket and the row is gone.
5. Negative: upload a non-video type or an oversized file → backend returns 400.
6. `./mvnw verify` green (ArchUnit incl. no-`now()`/no-field-injection, tests, frontend build). Add unit
   tests for object-key building and the upload validation (content-type/size), plus `VideoStorageService`
   behavior against MinIO if a lightweight integration test fits existing patterns.
